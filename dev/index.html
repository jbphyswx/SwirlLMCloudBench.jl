SwirlLMCloudBench.jl

Julia utilities for the Google Swirl-LM CloudBench ensemble: catalog constants, bucket URLs, a mutable download cache, lazy data.zarr access, parsed sounding.csv / parameters.json, and (with ClimaAtmos loaded) single-column forcing helpers.

See the README for a task-oriented guide, and the API page for the full reference.

Submodules

  • Catalog — case indices (0:499), seasonal months (1, 4, 7, 10), experiment IDs.
  • Paths — package-relative default roots.
  • Config — ENV-driven data_root / cache_root / raw_download_root.
  • CaseDirs — resolved_case_dir (canonical bucket layout).
  • Simulation — instances, simulations, URLs, downloads, Zarr, soundings, selection.

Data layout and caching

Routine downloads use a mutable, depot-local Scratch.jl cache (or SWIRL_LM_CLOUDBENCH_RAW_ROOT) laid out as the public bucket [root]/[site_id]/[month]/[experiment]/. The full ~2 TB data.zarr store is streamed lazily over HTTPS rather than mirrored; Pkg.Artifacts is not used for it (artifacts are immutable, fetched-whole blobs — a poor fit for a multi-terabyte store accessed in arbitrary subsets).
